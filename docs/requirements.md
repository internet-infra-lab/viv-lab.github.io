## 1. 项目概述

### 1.1 项目背景

高校科研实验室（课题组）普遍缺乏统一的对外展示窗口。现有信息散落在学校官网、导师个人主页、论文平台和社交媒体中，导致：

- 学术同行难以快速了解实验室研究方向与最新成果；
- 潜在学生（保研、考研、申请）难以判断实验室是否适合自己；
- 合作单位难以评估实验室实力与对接方式；
- 社会公众对科研工作缺乏了解渠道。

本项目的目标是建设一个**以内容展示为主、信息架构清晰、面向多类访客**的实验室官方网站。

### 1.2 产品定位

- **性质**：内容型展示网站（Content Site），非业务系统、非交互平台。
- **核心价值**：用最少的点击让访客回答三个问题 ——「这个实验室做什么？」「这里有什么人、什么成果？」「我如何加入/联系？」
- **调性**：专业、可信、开放、亲切。体现学术严谨性，同时降低对公众的理解门槛。

### 1.3 网站目标（Goal）

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 展示实验室研究方向与学术成果 | 让学术同行快速判断实验室的领域定位与科研水平 |
| G2 | 服务招生与人才引进 | 吸引优秀学生申请，为导师招募博士后/科研助理提供窗口 |
| G3 | 建立对外合作桥梁 | 为产学研合作、项目申报提供官方信息出口 |
| G4 | 传播科研价值 | 面向公众科普研究方向与社会价值，提升实验室影响力 |

### 1.4 范围界定（Scope）

**本期范围（In Scope）**：

- 全站 9 个一级栏目页面的前端建设与内容展示；
- 响应式布局（桌面端 / 平板 / 手机）；
- 基础检索与筛选能力（论文、新闻）；
- 中英文双语内容框架（文案结构预留，翻译量可分期交付）。

**不在本期范围（Out of Scope）**：

- 用户注册、登录、评论、论坛等交互功能；
- 在线表单提交（仅提供联系邮箱与电话，不建设后端表单系统）；
- 内容管理系统（CMS）后台开发（本期内容以静态数据/配置方式维护，CMS 作为后续迭代项）；
- 在线支付、电商类功能。

## 2. 目标用户与需求分析

### 2.1 用户画像

| 画像 | 人群 | 典型诉求 | 访问动机 | 关键内容 |
| --- | --- | --- | --- | --- |
| P1 学术同行 | 国内外同领域学者、审稿人 | 快速定位研究方向、代表论文、合作可能性 | 学术交流、引用、合作评估 | 研究方向、论文列表、项目 |
| P2 学生申请者 | 保研/考研本科生、在读硕士、海外申请者 | 判断课题组方向是否匹配、导师风格、毕业去向 | 择校择组 | 导师介绍、团队成员、招生招聘、新闻 |
| P3 合作单位 | 企业研发部门、政府/基金机构、兄弟院校 | 评估团队实力、寻找对接入口 | 项目合作、横向课题、成果转化 | 研究方向、科研项目、联系方式 |
| P4 社会公众 | 媒体、学生家长、科普爱好者 | 理解实验室在做什么、有何社会价值 | 科普了解、品牌信任 | 首页概览、新闻动态、科普向介绍 |

### 2.2 用户核心需求与对应解决方案

| 需求 | 描述 | 对应方案 |
| --- | --- | --- |
| 快速认知 | 30 秒内理解实验室是做什么的 | 首页首屏一句话定位 + 三大研究方向卡片 + 代表性成果 |
| 权威可信 | 内容真实、更新及时、有据可查 | 论文提供 DOI/期刊链接，团队成员有真实照片与简介 |
| 信息可达 | 三层点击内到达任意关键信息 | 全局导航 ≤ 9 项，面包屑导航，站内搜索 |
| 招生导向 | 申请者能一键找到申请入口与导师联系方式 | 招生招聘栏目 + 每页页脚常驻「联系我们」 |
| 多端适配 | 移动端浏览体验完整 | 响应式布局，移动端汉堡菜单 |
| 无障碍/国际化 | 面向公众与海外同行 | 中英双语框架、语义化 HTML、可访问性达标 |

### 2.3 用户旅程（典型场景）

**场景 A：学生申请者（核心场景）**

1. 通过搜索引擎/学长推荐进入首页；
2. 首屏看到定位与研究方向，产生兴趣；
3. 进入「导师介绍」了解导师履历与在招方向；
4. 浏览「团队成员」判断组内氛围与毕业去向；
5. 打开「招生招聘」查看申请要求与联系方式；
6. 通过页脚/联系页获取邮箱并发起申请。

**场景 B：学术同行**

1. 从论文/引用页面跳转进入；
2. 直达「学术论文」按年份/方向筛选最新成果；
3. 查看「研究方向」了解领域全貌；
4. 通过「科研项目」评估合作基础；
5. 联系实验室洽谈合作。

**场景 C：社会公众**

1. 从媒体报道/学校新闻进入首页；
2. 阅读「新闻动态」了解实验室近况；
3. 通过「实验室介绍」了解发展历程与科普向内容；
4. 无需深层次交互，浏览即完成目标。

## 3. 产品目标与成功指标

### 3.1 北极星指标

> **关键信息触达率**：访客在单次会话中成功访问 ≥1 个「决策型页面」（研究方向 / 导师介绍 / 招生招聘 / 学术论文）的比例。

### 3.2 辅助指标（上线后埋点观测）

| 指标 | 目标值（建议） |
| --- | --- |
| 首页跳出率 | ≤ 40%（学术类网站基准参考） |
| 平均会话时长 | ≥ 2 分钟 |
| 论文页平均停留 | ≥ 60 秒 |
| 移动端访问占比 | 适配良好，转化不劣于桌面端 |
| 招生季（9-10 月）咨询量 | 较上线前提升（由线下统计） |

## 4. 信息架构（IA）

### 4.1 站点地图（Sitemap）

```
实验室官网（一级域名 /）
│
├── 首页（/）
│
├── 实验室介绍（/about）
│   ├── 实验室概况
│   ├── 发展历程（时间线）
│   └── 实验室环境 / 平台设备（可选折叠页）
│
├── 导师介绍（/faculty）
│   └── 导师详情（/faculty/:id）—— 二级详情页
│
├── 团队成员（/team）
│   ├── 博士后 / 博士生 / 硕士生 / 科研助理 / 校友
│   └── 成员详情（/team/:id）—— 二级详情页
│
├── 研究方向（/research）
│   └── 方向详情（/research/:id）—— 二级详情页
│
├── 科研项目（/projects）
│   └── 项目详情（/projects/:id）—— 二级详情页
│
├── 学术论文（/publications）
│   ├── 按年份 / 方向 / 类型筛选
│   └── 论文详情（/publications/:id）—— 二级详情页
│
├── 新闻动态（/news）
│   ├── 新闻列表（分页）
│   └── 新闻详情（/news/:id）—— 二级详情页
│
├── 招生招聘（/join-us）
│   ├── 招生信息（本科/硕士/博士）
│   ├── 招聘信息（博士后/科研助理）
│   └── 申请流程与常见问题（FAQ）
│
└── 页脚全局区（全站可见）
    ├── 联系方式（邮箱 / 电话 / 地址 / 地图）
    ├── 快捷链接（招生招聘 / 论文 / 新闻）
    ├── 友情链接（学院 / 学校 / 合作单位）
    └── 版权与备案信息
```

### 4.2 导航设计原则

1. **全局导航 ≤ 9 项**：一级栏目共 9 项，超出时合并（如「实验室介绍」与「导师介绍」相邻分组）。
2. **三层点击原则**：任何关键内容从首页出发 ≤ 3 次点击可达。
3. **面包屑**：所有二级详情页展示面包屑导航。
4. **常驻转化入口**：全局导航与页脚均放置「招生招聘」入口；页脚常驻联系方式。
5. **高亮当前栏目**：全局导航高亮当前所在栏目，移动端汉堡菜单展开后同样高亮。

### 4.3 信息架构评审要点（供开发与评审使用）

- 9 个一级栏目是否均能从首页一层直达？—— 是，全局导航覆盖全部 9 项。
- 是否存在信息重复？（如「实验室介绍」与「关于我们」）—— 不设「关于我们」，统一用「实验室介绍」。
- 招生入口是否足够显眼？—— 导航第 8 位 + 页脚常驻 + 首页 CTA。

## 5. 页面级功能需求

> 约定：以下每个页面给出「页面目标 → 内容模块 → 功能要求」。模块按首屏至页脚的顺序排列。

### 5.1 首页（/）

**页面目标**：30 秒内建立实验室认知，分流四大类访客。

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 顶部导航栏 | Logo（实验室名称/简称）、9 项全局导航、语言切换（中/EN）、搜索入口 | 吸顶固定；滚动后压缩高度；移动端折叠为汉堡菜单 |
| 首屏 Hero 区 | 实验室一句话定位（如「面向 X 领域的智能系统实验室」）、主视觉图（实验室实拍/科研示意图）、2 个 CTA 按钮 | CTA1「了解研究方向」→ /research；CTA2「加入我们」→ /join-us；背景图懒加载 |
| 数据概览条 | 实验室规模数据（如：教师 X 人 / 学生 X 人 / 论文 X 篇 / 项目 X 项） | 数字滚动动画（可选）；数据与内容后台配置一致 |
| 研究方向速览 | 3~4 个研究方向卡片：图标 + 标题 + 一句话摘要 | 卡片整块可点击 → 方向详情页；悬停上浮动效 |
| 最新成果 | 最新 3~5 篇代表性论文（标题、期刊、年份、作者） | 点击跳转论文详情；标注「代表性论文」标签 |
| 新闻动态速览 | 最新 3~4 条新闻（标题、日期、分类） | 点击跳转新闻详情；提供「查看全部」→ /news |
| 招生招聘横幅 | 一句招募口号 + 当前在招岗位/名额 | CTA → /join-us；高对比底色区分于其他模块 |
| 页脚 | 联系方式、快捷链接、友情链接、版权备案 | 全站统一组件，见 5.10 |

### 5.2 实验室介绍（/about）

**页面目标**：建立实验室的完整认知与信任。

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 页面标题区 | 栏目标题 + 副标题（英文） | 所有二级页统一版式 |
| 实验室概况 | 2~4 段图文介绍：定位、历史、规模、特色 | 图文混排；长文支持「展开全文」 |
| 发展历程 | 时间线：成立年份起的重要节点（年、事件） | 纵向时间线组件；移动端适配为横向滚动或单列 |
| 平台与设备（可选） | 实验平台/仪器设备照片墙 + 简介 | 图片画廊，点击放大（灯箱） |
| 荣誉与资质（可选） | 获奖、认证、重点实验室资质 | 徽章/列表展示 |

### 5.3 导师介绍（/faculty）

**页面目标**：展示导师学术身份，支撑招生与同行评估。

**列表页**：

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 导师卡片网格 | 照片、姓名、职称、研究方向标签、邮箱图标 | 卡片点击 → 导师详情；邮箱图标可一键 mailto（需确认无爬虫风险，见开放问题 Q3） |

**详情页（/faculty/:id）**：

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 个人信息区 | 照片、姓名、职称、单位、联系方式 | 照片统一 3:4 比例 |
| 教育经历 | 时间线：学位、学校、专业 | 列表/时间线 |
| 工作经历 | 任职单位与时间 | 列表 |
| 研究方向 | 导师个人研究兴趣标签 | 标签可点击 → 对应研究方向详情页 |
| 代表论文 | 5~10 篇代表作（带 DOI 链接） | 复用论文条目组件 |

| 荣誉奖项（可选） | 获奖列表 | 列表 |

### 5.4 团队成员（/team）

**页面目标**：展示组内人员构成，增强申请者的代入感。

| 模块 | 内容 | 功能/交互要求 |

**数据说明**：成员信息涉及个人隐私，需在内容采集阶段获得本人授权（见风险 R3）。

| 模块 | 内容 | 功能/交互要求 |

### 5.6 科研项目（/projects）

**页面目标**：展示项目来源与体量，支撑合作评估。

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 筛选器 | 按项目类型（国家级 / 省部级 / 横向 / 国际合作）筛选 | 页签或下拉筛选 |
| 项目列表 | 项目名称、来源/编号、周期、负责人、简介 | 列表条目 → 项目详情 |
| 项目详情（/projects/:id） | 项目背景、目标、进展（可选）、相关成果/论文、参与成员 | 交叉链接到论文与成员 |

### 5.7 学术论文（/publications）

**页面目标**：完整、可信、可检索的成果库。**本栏目为同行访问最高频栏目，优先保证体验。**

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |
| 筛选/排序 | 按年份、研究方向、论文类型（期刊/会议/专利）筛选；按年份倒序/正序排序 | 组合筛选；空结果显示「无匹配结果」及重置按钮 |
| 论文列表 | 作者（通讯作者加粗/标注）、标题、期刊/会议名、年份、DOI/链接 | 整条可点击；DOI 新窗口打开；高亮通讯作者 |
| 论文详情（/publications/:id） | 摘要、关键词、引用信息、全文/预印本链接 | 引用格式复制按钮（GB/T 7714 或 APA，见开放问题 Q2） |
| 年度统计（可选） | 近五年发文量柱状图 | 轻量图表组件 |

**字段规范**：作者顺序、通讯作者标注、DOI 有效性需在内容录入阶段校验（见 7.4）。

### 5.8 新闻动态（/news）

**页面目标**：保持网站活力与时效性，支撑科普与传播。

| 模块 | 内容 | 功能/交互要求 |
| --- | --- | --- |

## 7. 内容与字段规范

### 7.2 关键字段定义（供前端数据结构设计参考）

**论文（Publication）**

| venue | string | 是 | 期刊/会议名称 |
| year | number | 是 | 发表年份 |
| type | enum | 是 | 期刊 / 会议 / 预印本 / 专利 |
| doi | string | 否 | DOI 或 URL |
| abstract | string | 否 | 摘要 |
| keywords | array | 否 | 关键词 |
| research_direction | array | 否 | 关联研究方向标签 |

**导师 / 成员（Person）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 唯一标识 |
| name | string | 是 | 姓名 |
| photo | string | 否 | 照片 URL |
| title | string | 是 | 职称/身份（教授、博后、博士生…） |

**新闻（News）**：`id`、`title`、`date`、`category`（实验室动态/学术活动/获奖荣誉/媒体报道）、`cover`（可选）、`summary`、`content`、`source`（可选）。

**项目（Project）**：`id`、`title`、`type`（国家级/省部级/横向/国际合作）、`number`（项目编号）、`period`（起止时间）、`pi`（负责人）、`summary`、`status`（进行中/已结题）。

**方向（ResearchDirection）**：`id`、`title`、`icon`、`summary`、`content`、`related_keywords`。

### 7.3 文案规范

- 全站中文为主，英文为副；术语保持中英对照首次出现格式：`深度学习（Deep Learning）`。
- 一级栏目名统一为 4~6 字中文：实验室介绍 / 导师介绍 / 团队成员 / 研究方向 / 科研项目 / 学术论文 / 新闻动态 / 招生招聘。
- 避免绝对化表述与夸大宣传；涉及数据（人数、论文数、项目数）需与实际一致。

### 7.4 内容质量要求

1. 论文 DOI 必须可访问，失效链接需人工复核；
2. 作者顺序与通讯作者标注必须与原文一致；
3. 导师/成员照片需获得本人授权；
4. 新闻日期与来源需真实可溯。

### 7.5 数据维护方式（本期约定）

- 本期前端以**独立数据文件/目录**承载内容（如 `data/` 目录下的 JSON/Markdown），页面结构与之解耦；
- 命名规范：`publications.json`、`people.json`、`news/*.md`、`projects.json`、`directions.json`；
- 为后续 CMS 迭代预留统一字段结构（与 7.2 一致）。

## 8. 交互与视觉设计需求

### 8.1 视觉风格

| 维度 | 要求 |
| --- | --- |
| 风格关键词 | 专业、简洁、学术、可信；避免花哨动效与高饱和撞色 |
| 主色 | 建议取学校/学院品牌色，辅以深蓝/墨绿等学术感色调；需提供色板与对比度说明 |
| 字体 | 中文衬线标题 + 无衬线正文的经典学术组合，或全无衬线（由设计师定稿）；建议正文 ≥16px |
| 版式 | 网格化布局；留白充足；论文/成员等列表统一卡片式 |
| 图片 | 统一裁切比例：成员照片 3:4，新闻封面 16:9，Hero 16:9 |

### 8.2 交互规范

| 编号 | 规范 | 说明 |
| --- | --- | --- |
| I-01 | 悬停反馈 | 所有可点击卡片/按钮有悬停态（上浮、变色或阴影），持续 ≤200ms |
| I-02 | 焦点可见 | 键盘 Tab 导航时焦点环清晰可见（可访问性） |
| I-03 | 加载反馈 | 页面切换/图片加载有骨架屏或加载指示 |
| I-04 | 动效克制 | 动效仅用于引导注意，不阻塞操作；尊重 `prefers-reduced-motion` |
| I-05 | 滚动位置 | 列表筛选/翻页后滚动回列表顶部 |
| I-06 | 分享/复制 | 复制引用格式成功后给出 Toast 提示 |

### 8.3 可访问性（A11y）

- 语义化 HTML（`header` / `nav` / `main` / `article` / `footer`）；
- 图片 `alt` 文本全覆盖；
- 对比度满足 WCAG 2.1 AA；
- 所有交互元素可用键盘操作；
- 视频/动图不得自动播放循环（若有）。

## 10. SEO 与数据埋点需求

### 10.1 SEO 要求

| 编号 | 要求 | 说明 |
| --- | --- | --- |
| S-01 | 语义化标签 | 每页唯一 `h1`；层级清晰 |
| S-02 | Meta 信息 | 每页独立 `title`（≤30 字）、`description`（≤80 字）、`keywords`（可选） |
| S-03 | 结构化数据 | 论文页使用 Schema.org `ScholarlyArticle`；导师页使用 `Person`；机构信息用 `Organization` |
| S-04 | URL 语义化 | 使用 7.2 定义的语义化 slug（如 `/publications/semantic-segmentation-2024`），不使用无意义 ID |
| S-05 | Sitemap | 提供 `sitemap.xml` 与 `robots.txt` |
| S-06 | 规范链接 | 全站无重复内容；`canonical` 正确 |
| S-07 | 图片 SEO | 图片 `alt` + 描述性文件名 |

### 10.2 数据埋点

- 全站接入统计（推荐 Plausible / Umami 等轻量方案或学校指定统计）；
- 必埋事件：首页 CTA 点击、招生页访问、论文页访问、搜索关键词；
- 埋点不采集个人信息，符合隐私合规要求。
